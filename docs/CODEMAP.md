# Code map — where to edit what

Task routing for agents and humans. Architecture lives in `PLAN.md`; wire format in
`protocol/PROTOCOL.md`. Step-by-step workflows in `docs/AGENT-RECIPES.md`.

For what remains to implement and experimental-alpha scope, start with
[SYNC-SCOPE-AUDIT.md](SYNC-SCOPE-AUDIT.md), then the detailed
[coverage roadmap](COVERAGE-ROADMAP.md). Historical catalog/adapter registration is
not whole-feature completion.

## Partial-class convention

Large types split by concern, e.g. `FsmWorldSync.cs` + `FsmWorldSync.Remote.cs`.
When a file approaches ~1000 lines, add a new partial — don't grow a monolith.

Shopping bag identity/ownership and opening: `ItemWorldSync.BagBindings.cs` (native
factory IDs, catalog guards, preserved guest save objects), `.Bags.cs` (host ledger,
opening lifecycle, publication), `.BagReplicas.cs` (guest visuals and requests),
`.BagSpill.cs` (exact native output capture, persistent bag parts and prefab names), `.BagPickup.cs`
(native hand ownership). Generic spill replay/retry lives in `.Spawn.cs`;
`.SavedProducts.cs` reconstructs loose saved groceries from validated templates
(v214). `BagSpillChecks.SavedProducts.cs` covers reconstruction;
`LiveBagProbe.Persistence.cs` drives disposable save/restart/rejoin checks.
Engine-free bag policies/messages are `BagOpenLedger`, `BagStatePolicy`, `BagMessages`.
Terminal native spill completion is checked in `.Bags.cs` / `.BagBindings.cs`;
numbered drink consumption states are validated in `Catalog/VehicleCatalogConfig.cs`.
Developer regressions: `tools/GuestSaveProbe/BagSpillChecks.cs` and the opt-in
two-process shopping driver `LiveBagProbe.cs` (see BUILDING.md).
